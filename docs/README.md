# OctoAcme Project Management Docs

A central index to OctoAcme's project management guidance. OctoAcme manages cross-functional work through clear ownership, iterative delivery, customer-focused outcomes, and data-informed decisions.

## Process overview

Projects begin with **initiation**, where the team validates the business need, identifies stakeholders, defines measurable success criteria, and decides whether to proceed. In **planning**, the team turns approved work into a prioritized backlog with acceptance criteria, estimates, a Definition of Done, milestones, and identified risks and dependencies. During **execution**, teams deliver in small increments, track work on a project board, and use reviews and testing to maintain quality. **Release** includes readiness checks, deployment verification, and rollback planning. Teams then **close and improve** through retrospectives that capture learnings as owned action items. Risks and dependencies are monitored throughout, with blockers escalated through the agreed path.

The **Project Manager (PM)** coordinates delivery, schedules, risks, resources, and communications; the **Product Manager (PdM)** defines outcomes, prioritizes work, and measures success. Developers implement and test the work, QA/testing validates quality and acceptance criteria, and stakeholders provide input and approvals. Regular team standups, PM–PdM and delivery syncs, stakeholder updates, and milestone demos keep progress and decisions visible. Quality practices include unit tests for new logic, integration tests where applicable, end-to-end smoke tests for critical flows, CI tests and linting, security scanning, and manual QA when needed. Release checks confirm acceptance criteria and passing CI/security scans, with post-deployment verification and rollback/mitigation plans.
